# PRD-005 — `/gallery` (GalleryTech) — Integridad de medios + kind `youtube` + enlaces externos

> Estado: **APROBADO** — implementación en curso (pedido explícito del usuario, 17-oct-2026).
> Correlativo: `PRD_005` (antes de tocar código, obligatorio por `AGENTS.md`).
> Base: `PRD_003` (v1 Technopunk) + `PRD_004` (full-width, v0.4.0 implementada y testeada).

## 1. Contexto y problema

Tras revisar la preview local en Windows, el usuario reporta:
- Los ítems 01–04 (imágenes) **no visualizan nada**; los videos ("mappings") sí se ven.
- Necesita saber **dónde agregar medios nuevos** y quiere soportar **YouTube y enlaces externos**.

Diagnóstico (verificado con curl + Chrome headless en esta iteración):

1. **URLs falsas en la semilla**: los ítems 01–02 apuntaban a URLs `https://utfs.io/f/…` fabricadas durante el seed inicial → **404** (confirmado con curl). Las dimensiones de sus metas (800×800, 615×1060) también eran inventadas.
2. **Normalización a producción rota**: `normUrl()` (SSR) y `norm()` (runtime) reescribían todo path local (`/visuales.svg`, `/images/album/…`) a `https://lllitmts.vercel.app/…` — y **ese dominio responde 404: el sitio aún no está desplegado**. En `pnpm dev`, ningún asset relativo cargaba; solo funcionaban las URLs absolutas remotas (videos `ufs.sh`) → "los mappings sí están". Este es el bug raíz de los ítems 03–04 (y de thumbs, posters y preload).
3. **Asset mal atribuido**: `logo-stack.svg` (ítem 03) resultó ser un logotipo estilo *Grand Theft Auto* (id interno `GTA_Stack`), no la identidad LLLIT; el alt/título de la semilla eran incorrectos. Repro headless confirmó además que **el patrón `<picture>`/flex SÍ renderiza** — no existía bug de CSS.
4. **Posters de videos** apuntaban a las mismas URLs utfs.io 404 → caja negra hasta cargar metadata.

## 2. Objetivo

Restaurar la visualización completa de la galería (medios locales y remotos) y extender el contrato de datos con: `kind: "youtube"` (facade click-to-play) y enlaces externos opcionales (`href`/`hrefLabel`) por ítem — dejando `src/data/gallery.ts` documentado como único punto de edición.

## 3. Alcance (IN / OUT)

### IN
- **Medios same-origin**: paths relativos en SSR y runtime; se elimina `normUrl`/`norm` para medios (queda `site` solo para el link de compartir canónico).
- **Semilla corregida**: assets reales `/images/album/cover-small.*` (1400²) y `/images/album/visual-bg.*` (3000²); aspects reales (`1/1`, `16/9`); posters de videos con assets reales.
- **Ítem 03** corregido a wordmark LLLIT (`/mts.svg`, variante blanca visible sobre stage oscuro); `logo-stack.svg` (GTA) queda fuera y se documenta.
- **`kind: "youtube"`**: `src` = URL completa (watch/youtu.be/shorts/embed) o ID de 11 chars; thumbnail automático `i.ytimg.com/vi/<id>/hqdefault.jpg` con override `poster`; **facade** click-to-play (`youtube-nocookie.com/embed/<id>?autoplay=1&rel=0`); fallback `<a>` si el ID no parsea; soporte en stage, lightbox y lista.
- **`href?: string` + `hrefLabel?: string`** en cualquier ítem: botón `[ETIQUETA ↗]` en la barra del stage (`target="_blank"`, `rel="noopener noreferrer"`), oculto si no hay `href`.
- **Doc de uso** ampliado en el header de `src/data/gallery.ts` (image / video / youtube / href) — el usuario pidió el path "para probar".
- **Semilla demo**: ítem YouTube real del canal + `href` Bandcamp en la carátula.
- Tests PRD-005 + contrato de kinds actualizado + bump `v0.4.0 → v0.5.0`.

### OUT
- Deploy (lo hará el usuario; el fix asume same-origin en dev y prod).
- Botón de enlace externo en el lightbox (solo barra del stage; futura iteración).
- Otros embeds (Vimeo/Spotify/SoundCloud): el patrón facade queda listo, pero solo YouTube ahora.
- Extracción de frames reales para posters (sin ffmpeg en WSL): posters provisorios con assets reales del álbum.

## 4. Decisión arquitectónica

1. **Medios same-origin (relativos)**: la absolutización previa rompía dev y no aportaba (og/sitemap manejan sus URLs por su cuenta). `site` permanece únicamente para construir el link de compartir canónico.
2. **Facade YouTube, nunca iframe eager**: 0 cookies de YouTube hasta el click, 0 costo de performance en la carga; el `<button>` overlay es CSS-only y se reemplaza por el iframe al reproducir. `youtube-nocookie` + `allow="autoplay; encrypted-media; picture-in-picture; fullscreen"`.
3. **Parseo de ID robusto**: una regex acepta `watch?v=`, `youtu.be/`, `embed/`, `shorts/` y ID desnudo; si no parsea → link directo (degradación honesta, sin iframe roto).

## 6. A11y

- Facade = `<button>` real con `aria-label="Reproducir video: <alt>"`; iframe con `title` = alt del ítem.
- Botón de enlace con texto visible; `rel="noopener noreferrer"`; `[hidden]` con regla CSS explícita (`.gt-btn[hidden]`) para no romperse por especificidad.
- Focus-visible global vigente; reduced-motion sin cambios; orden de tab intacto.

## 7. Optimización

- Thumbs de lista: YT thumbnail remoto (`hqdefault.jpg`, ≈15 KB) o `poster` local; jamás iframe en lista.
- Facade no carga el iframe hasta la interacción; `loading="lazy"` en thumbnails e iframe.
- Preload del cover ahora sí resuelve same-origin (`/images/album/cover-small.webp`); los posters reutilizan assets ya usados por la galería (caché del navegador).

## 8. Decisiones abiertas

- Enlace externo dentro del lightbox: NO en esta iteración (solo barra del stage).
- Posters reales por frame de video: requiere ffmpeg (fuera de WSL); el usuario puede reemplazar `poster` cuando quiera.
- Otros embeds (Vimeo/Bandcamp player): patrón facade documentado, implementación futura.

## 10. Riesgos y mitigaciones

| Riesgo | Mitigación |
|---|---|
| `ytimg.com` bloqueado/offline | `poster` override local + fallback `<a>` si el ID no parsea |

| Validación visual final | usuario en Windows con checklist §12 |

## 14. Hotfix v0.5.1 — overflow de imágenes en stage/lightbox (17-oct-2026)

**Reporte del usuario:** "las imágenes desbordan su espacio; los videos OK".

**Causa raíz (verificada con Chrome headless):** el `<picture>` — wrapper exclusivo de imágenes; los videos no lo tienen — no recibía tamaño propio y el `<img>` interior usaba porcentajes → dependencia circular de sizing; como flex item, el `<picture>` caía a su tamaño intrínseco (1400 px) y desbordaba el marco del stage/lightbox. `object-fit:contain` no puede contener si la caja misma está sobredimensionada.

**Evidencia (repro local en `.repro-tmp/`, eliminado tras verificar):** variantes A/D (código anterior) desbordan; B/E (fix) contenidas; C (patrón video) contenida.

**Fix:** el `<picture>` pasa a ser la caja dimensionada (`width/height:100%` + `aspect-ratio` + cap `dvh` en lightbox) y el `<img>` interior se resuelve con `width/height:100%` + `object-fit:contain`. Aplica en el featured SSR y en `mediaHTML()` (stage + lightbox). **Videos intactos** (su patrón ya era correcto). Bump `v0.5.0 → v0.5.1`.
