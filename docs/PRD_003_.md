# PRD-003 — Sección `/gallery` (Arte) — Sistema «Technopunk Enterprise»

> Estado: **DISEÑO** — siguiente paso: implementación.
> Correlativo: `PRD_003` (antes de tocar código, obligatoria por `AGENTS.md`).

## 1. Contexto y problema

El sitio `lllitmts` hoy expone su contenido en estéticas coherentes entre sí (Y2K Brutalista en páginas internas, Cyber-Punk en hero de home). El usuario quiere **una sección de arte `/gallery`** con un diseño propio, **Technopunk Enterprise**, que conviva con las demás sin contaminar el design system global del sitio.

Conflicto detectado en el pedido: el spec Technopunk usa `#A855F7` como acento principal, pero también define `High-Contrast Purple` `#B14BFF`. Se toma `#A855F7` como acento 2 (Cybergoth Purple) por ser el valor primario declarado en la columna de acentos; `#B14BFF` queda como variante "high contrast" reservada para estados activos/hover donde se necesite empujar más contraste (ver §6 Accesibilidad).

## 2. Objetivo

Crear la sección `/gallery` (Arte) del sitio LLLIT como **sub-sistema visual autocontenido** con estética Technopunk Enterprise, donde el usuario pueda agregar/remover trabajos (videos por URL e imágenes) editando **un único archivo de datos** y redirmando (code-redploy), con optimización profesional de assets y accesibilidad WCAG.

## 3. Alcance (IN / OUT)

### IN
- Nueva ruta SSR: `GET /gallery` (y optionally `GET /gallery.xml` NO — fuera de alcance).
- Fuente de datos única, tipada, editable: `src/data/gallery.ts` (con export default + interfaces).
- Componente visual encapsulado: `src/components/gallery/GalleryTech.astro` (window-frame + grilla + lightbox), con estilos scoped (`.gallery-tech`), JS inline ( GSAP solo para efectos de UI que el spec pida; la interacción principal es CSS + vanilla JS).
- Ingesta de 2 tipos de media: **imagen** (`.webp`/`.jpg`/`.png` por URL) y **video** (`.mp4`/`.webm`/URL remota con poster `posterUrl`). Cada entrada tiene `alt`, `tags`, `aspect`, `title`, `meta` (año, tipo, notas).
- Optimización: `aspect-ratio` explícito (sin CLS), `loading="lazy"` + `decoding="async"` (excepto el primer ítem = `eager` + `fetchpriority=high`), `source` webp cuando exista, `preload` de posters via `<link>` solo para el hero/cover.
- SEO: página con `CollectionPage` + `ImageGallery`/`VideoObject` en JSON-LD, canonical único, breadcrumbs, OG/Twitter local, actualización de `sitemap.xml` y `llms.txt`.
- Accesibilidad: WCAG 2.1 AA como mínimo, contraste ≥ 4.5:1 para texto principal; `aria-live` en lightbox; `prefers-reduced-motion` respetado (GSAP matchMedia obligatorio, CSS `transition: none` bajo reduce); foco visible (`:focus-visible`); teclado completo (Esc, arr, Tab).
- Nav: link agregado en `HeaderShared` (label `Arte` → `/gallery`) y, si aplica, en el footer existente.
- Tests: `tests/gallery.test.js` (smoke: archivo existe, data no vacía, sitemap contiene `/gallery`, llms.txt mención, JSON-LD presente en el HTML renderizado vía import estático de la data).
- Reindex MCP final (persistence).

### OUT
- CMS / panel admin.
- Modo "High-Readability" completo como switch de tema (se implementa la variante de contraste como **estado hover/focus** accesible, no como modo alternativo del sitio).
- Migración de datos existentes a un CMS.
- Galería paginada / infinito scroll (la colección es finita y pequeña).
- Backend de upload (el usuario sube los assets a la infra actual: `public/` o CDN/URL externa).

## 4. Decisión arquitectónica clave (importante)

El spec Technopunk **NO reemplaza** el design system Y2K/Cyber global. Se aplica como **sub-tema scoped** bajo el selector `.gallery-tech` (o un wrapper `<section class="gallery-tech">`). Racional:

1. El resto del sitio mantiene su identidad (tokens Y2K, tipografías GTA, acento amarillo `#FDE047`, brutalismo).
2. El sub-tema usa **variables CSS locales** (`--gt-*`), no globales, para no colisionar con el toggle `light/dark` global (`ThemeToggle.astro`). La galería **siempre finta dark** (`#090C10`), independiente del tema del sitio.
3. Tipografía mono (`JetBrains Mono`/`Fira Code`/`Space Mono`): en el sitio hay `GTA` + `GTS` (sans). **No hay mono self-hosted**. Para no descargar otra fuente y mantener LCP, se usa un **fallback stack mono** (`JetBrains Mono, Fira Code, Space Mono, ui-monospace, monospace`) y se agregan las fuentes solo si el usuario pide branding exacto. (Se deja como decisión ABIERTA en §8.)
4. El lightbox y la interacción de la galería se aíslan en el componente `GalleryTech.astro` con `gsap.context()` + `matchMedia` (pattern del sitio), cleanup en la callback de return.

## 5. Ingesta modular de datos (el corazón del pedido)

### 5.1 Contrato de datos

`src/data/gallery.ts` — **única fuente de verdad**. Editarse = agregar/remover obras. Redeploy vía CI/CD actual (Vercel).

```ts
export type GalleryItemKind = "image" | "video";

export interface GalleryItem {
  /** id estable para anclas/accessibilidad */
  id: string;
  kind: GalleryItemKind;

  /** URL absoluta o ruta relativa (public/) del asset */
  src: string;
  /** URL del poster (solo video) — recomendado para CLS/lazy */
  poster?: string;

  /** variantes de formato para <picture> / source webp (opcional) */
  srcWebp?: string;

  /** alt text accesible (obligatorio por código y test) */
  alt: string;

  /** título visible de la obra */
  title: string;
  /** metadata: año, técnica, dimensión, notas (línea mono pequeña) */
  meta?: string;
  /** tags para filtrado futuro / display (chips) */
  tags?: string[];

  /** aspect ratio explícito para reservar caja (anti-CLS) — "16/9" etc. */
  aspect?: string;

  /** true → primer ítem (eager + fetchpriority="high") */
  featured?: boolean;
}

export const gallery: GalleryItem[] = [ /* … */ ];
```

### 5.2 Reglas duras de ingesta
- **Toda entrada tiene `alt`** (test lo verifica; no puede ser vacío).
- **`aspect` obligatorio si no hay `poster`** en video → se reserva la caja con `aspect-ratio`.
- **`featured`** solo una por colección (el primero sin flag es el fallback); el componente renderiza el featured como **cover/hero de la galería** con `fetchpriority="high"` y el resto `lazy`.
- URLs: se aceptan absolutas (`https://…`) o relativas a `public/` (`/gallery/foo.webp`). El componente normaliza.
- Orden del array = orden de exhibición. (Sin sort — estabilidad y predictibilidad.)
- Agregar nuevo tipo de media (audio, 3d, pdf) → se extiende `GalleryItemKind` + un caso en el renderizador (única "rama" abierta del módulo).

### 5.3 Flujo de update (código-verificado)
1. Usuario sube asset a `public/gallery/<id>.webp` (o URL remota).
2. Editar `src/data/gallery.ts` (agregar entrada).
3. Commit → push → Vercel build → online.
No hay paso extra. El test `gallery.test.js` protege al menos: no-vacío, `alt` presente, `aspect` o `poster` presente.

## 6. Diseño Technopunk Enterprise (mapeo al spec)

### 6.1 Tokens locales (`.gallery-tech`)
```css
/* dentro de <style> del componente, scoped — NO globales */
.gallery-tech{
  --gt-bg:        #090C10; /* Deep Terminal Black */
  --gt-panel:     #161B22; /* Window Charcoal */
  --gt-border:    #30363D; /* Metal Frame Gray */
  --gt-ink:       #F0F6FC; /* High-Contrast White */
  --gt-muted:     #8B949E; /* Code Muted Gray */
  --gt-accent-1:  #00FF66; /* Terminal Hack Green */
  --gt-accent-2:  #A855F7; /* Cybergoth Purple */
  --gt-accent-2-hc:#B14BFF; /* High-Contrast Purple (hover/focus) */
  --gt-alert:     #FF3366; /* Industrial Red       */
}
```

### 6.2 Estructura visual (window-frame del spec)
```
┌──────────────────────────────────────────────────┐
│ ● ● ●   LLLIT.OPS — GALLERY.SYS    v0.3.1   [X]  │  header (mono, borde inferior)
├──────────────────────┬───────────────────────────┤
│  ● PROTOCOLO ACTIVO  │                           │
│  ▸ lista de obras    │   ANTEVISTA               │
│    (mini-cards 2col) │   (media grande, 16/9 o   │
│                      │    el aspect de la obra)  │
│  [FILTRO] [DESCUBRIR]│                           │
│                      └───────────────────────────┘
│  [SISTEMA ESTABLE] [NUEVO: 3 WORKS]   STATUS: OK │  footer chips
└──────────────────────────────────────────────────┘
```
- **Desktop:** 2 columnas (lista 42% / preview 58%). Click en item de la lista → la preview cambia (fade corto, sin scroll).
- **Mobile:** 1 columna, lista arriba (scroll interno), preview debajo sticky-top opcional; o toggle por tab `LISTAR | VER`. (Se decide en implementación; por defecto: lista colapsable + preview full-width bajo.)
- **Lightbox (full-screen)** al hacer click en el media grande: `role="dialog"`, foco atrapado, `Esc`/click-fuera cierra, arr izq/der navega, contenedor `.gallery-tech` mantiene context. Imagen: `<img>` con `max-h/max-w` y `object-contain`. Video: `<video controls preload="metadata">`, autoplay **solo si `not reduced-motion`** y con `muted` cuando autoplay por gestos del browser no aplica (política: autoplay **off** por defecto, `controls` siempre).

### 6.3 Componentes del spec (mappings)
- **Status Badge** → chip en el header de la window: `SYS OK` (green border), `SYNC` (purple), `WARN` (red). Usarse para mostrar estado de carga del video (`preload`) y error de load.
- **Action Button (Primary)** → botón `[DESCUBRIR]` (accent-1, black text, blur+underline en hover) que dispara lightbox.
- **Secondary Button** → `[EXPORTAR]`/`[COMPARTIR]` (outline `--gt-border`, hover panel+purple text). `COMPARTIR` usa `navigator.share` con fallback a `copy` a `clipboard` y a un toast inline (`aria-live="polite"`).
- **Terminal Input** → no hay login; se mantiene el **filtro por tag** como `input` con estilo terminal (accent-1 text, mono, `caret-color`), filtrando la lista sin recarga.
- **Navigation Bar / User Input** → header de la window (● ● ● título vX.Y [X] = botón cerrar/ocultar la galería), y el `meta` de la obra como línea de input-estilo.
- **Full Screen Terminal (Preview)** → la preview 58% + lightbox.
- **Grid (4 col desktop)** → solo aplica si la vista cambia a "cuadrícula" (fuera de alcance v1; se deja `data-view="list|grid"` para v2 sin romper).
- **Scanlines** → capa `::after` `pointer-events:none`, opacity ≤ 0.05, **desactivada bajo `prefers-reduced-motion`** (flicker) y opcional en print.
- **Window/Panel/Sidebar/Drawer** → la window principal + panel izquierdo = sidebar; drawer = lightbox (movimiento Y corto, `ease: power3.out`, 0.2s).

### 6.4 Motion (estable, 0.15–0.2s)
- Entrada de window: `fromTo` opacity+`translateY(12px)`, stagger de chips 0.02.
- Hover de item: `border-color` + `box-shadow (0 0 0 1px accent)` 0.15s.
- **Obligatorio:** `gsap.matchMedia` con `prefers-reduced-motion: reduce` → sin animación; fallback a `autoAlpha` solo en `no-preference`. Nada de `visibility:hidden` por default (progressive enhancement, patrón del sitio).

### 6.5 Accesibilidad (WCAG 2.1 AA, metas AAA en contraste)
- Contraste: `--gt-ink` sobre `--gt-bg` > 15:1 ✓; `--gt-muted` sobre `--gt-bg` ≈ 5.4:1 ✓ (AA cuerpo); **`--gt-accent-1` sobre `--gt-bg` ≈ 12.6:1** ✓ para texto verde; `#FF3366` sobre `#090C10` ≈ 6.1:1 ✓ (AA). Para hover/focus de texto frágil se empuja a `--gt-accent-2-hc` `#B14BFF` (≈ 7.4:1) — por eso existe como variante.
- **Foco visible:** `:focus-visible { outline: 1px solid var(--gt-accent-2-hc); outline-offset: 2px; }` en todos los interactivos de `.gallery-tech`.
- **Lightbox** con `aria-modal="true"`, `role="dialog"`, `aria-label` con título de la obra, focus-trap simple (Tab cicla dentro, Shift+Tab igual), `Esc` cierra y **devuelve el foco** al elemento que abrió.
- **`aria-live="polite"`** en el toast de compartir y en el status de carga de video.
- **Alt** obligatorio y descriptivo (no "imágen 1"), y **título + meta** también como `aria-label` accecible del ítem.
- **Media:** `<video>` con `controls` y `aria-label`; poster siempre que exista para no forzar decode.
- **Reduced motion:** sin scanlines, sin stagger, sin autoplay (ver §6.2), transiciones CSS `none` bajo `@media (prefers-reduced-motion: reduce)` (pattern del sitio `Footer.astro`/FAQ).

## 8. Decisiones abiertas (NO bloquean la implementación de v1)

1. **Fuente mono exacta**: fallback stack (recomendado, 0 costo LCP) vs self-hoster `JetBrains Mono` en `/public/fonts/` (branding exacto). Por defecto: stack.
2. **Vista grid (4 col)** del spec: v1 = list+preview (2 paneles); v2 opcional con `data-view`.
3. **Videos remotos**: si el usuario da URLs externas a `public/` (CDN/UT), se agregan `referrerpolicy="no-referrer"` y `preload="metadata"`; si son locales, `preload="none"` + poster. Por defecto: `preload="metadata"` en lightbox, `none` en lista.
4. **Compartir**: `navigator.share` → clipboard → toast. (Si no hay share API en mobile, clipboard solo.)

## 9. Optimización "profesional" (checklist)

- ✅ `aspect-ratio` en toda media (anti-CLS) — del dato (`aspect`) o `16/9` fallback para video.
- ✅ Primer ítem: `loading="eager"` + `decoding="async"` + `fetchpriority="high"` + `<link rel="preload" as="image">` (solo imagen featured).
- ✅ Resto: `loading="lazy"` + `decoding="async"`.
- ✅ `<picture>`/`source` webp cuando `srcWebp` existe (patron `album/index.astro`).
- ✅ Videos: `preload="metadata"` + poster; en lista **no** se carga el video (solo poster) — el video real carga en lightbox.
- ✅ `content-visibility: auto` + `contain-intrinsic-size` en la lista de items (si la colección crece).
- ✅ Sin JS = galería funcional: los ítems son `<figure>` con media visible (lightbox pierde la UX rica pero las obras siguen siendo acccesibles/enlazadas).
- ✅ CSS del componente en `<style>` scoped, sin estilos globales que colisen con Y2K.
- ✅ `llms.txt` + `sitemap` al día.

## 11. Riesgos / Mitigaciones

| Riesgo | Mitigación |
|---|---|
| Colisión de tokens con tema global | Variables **locales** `--gt-*` en `.gallery-tech` (nada de `:root`); la galería finta dark fijo |
| CLS en videos remotos | `aspect-ratio` obligatorio en dato + poster; en lista solo poster (no video) |
| Autoplay bloqueado por browsers | `controls` siempre, autoplay nada (o solo bajo `no-preference` + `muted`); nunca depender de autoplay |
| Contraste de `#A855F7`/`#FF3366` en texto pequeño | Usar solo para acentos/bordes/texto ≥ 14px bold, o empujar a `--gt-accent-2-hc` en focus/hover |
| Scanlines → flicker / usabilidad | Opacity ≤ 0.05, `pointer-events:none`, off bajo reduced-motion |
| Colección crece y el JS pesa | `content-visibility` + lista filtrada client-side sin recarga; video solo en lightbox |
| Semillas con assets del sitio que luego se mueven | `src` relativo a `public/` con paths estables (`/gallery/...`) |

## 13. Criterios de aceptación

- [ ] `GET /gallery` retorna 200 y muestra la colección del archivo de datos (sin HTML hardcodeado de obras).
- [ ] Agregar 1 entrada a `src/data/gallery.ts` + redeploy → aparece en la galería (flujo §5.3).
- [ ] Zero CLS: toda media con `aspect-ratio` reservado.
- [ ] Teclado: Tab/Shift+Tab/Esc/flechas operan lightbox y filtro; foco visible en todos.
- [ ] `prefers-reduced-motion: reduce` → sin animaciones, sin scanlines, lightbox instantáneo.
- [ ] Contraste AA en todos los pares texto/fondo usados (verificados §6.5).
- [ ] JSON-LD válido (rich results: ImageGallery/VideoObject).
- [ ] `node --test tests/*.test.js` → 0 fallos.
- [ ] Sin estilos globales fugados del sub-tema (`.gallery-tech` aísla tokens).

## 14. Criterios de rendimiento (metas)

- LCP < 1.2s (rAF realista) con el primer asset `fetchpriority=high` + `preload`.
- TBT: JS de la galería < 3KB gzip (vanilla + GSAP ya cargada por el sitio).
- CLS = 0 en galería por diseño.
- Sin peticiones de video en la lista (solo poster); 1 solo video en lightbox a la vez.
